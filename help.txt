----------------------------------------------------------------
  一、插件概览
----------------------------------------------------------------
BiliKards 是一个 KARDS B 站助手插件，包含两大核心功能：

  A. 官方动态查询
     - 查询 KARDS 官方最新动态、相关视频、关注数等
     - 提取图文混排的正文、标题、封面图、转发原文链接
     - 按段落分段并按帖发送，支持配图

  B. 卡组代码解析与图像渲染
     - 解析 KARDS 卡组导入码（%%<main><ally>|...）
     - 将卡组拆解为卡牌条目，含阵营、类型、稀有度、费用等
     - 自动渲染卡组信息图 + 卡牌全图

----------------------------------------------------------------
  二、配置项（位于 _conf_schema.json）
----------------------------------------------------------------
  kards_uid              插件 B 站 UID，默认 2127596945（KARDS官方）
  max_items              单次展示动态条数，默认 5
  cache_ttl              动态缓存时间（秒），0 表示不缓存，默认 300
  send_pics              是否推送图片，关闭后动态只发文字，卡牌搜索也不附带卡图
  max_pics_per_item      每条动态最多推送的图片数，0 表示不推送图片，默认 9
  deck_image             卡组是否生成卡组图片，关闭后只发送文字卡表
  vision_provider_id     卡图识别使用的视觉模型，默认 openai-responses/Sage-S2.1-Flash
                         识别失败或超时会自动回退到其他图片模型
  bili_proxy             B 站请求代理，如 http://127.0.0.1:7890；服务器 IP 被 412 风控时填写
  bili_cookie            B 站登录 Cookie，如 SESSDATA=xxx; buvid3=xxx；与代理二选一或同时填

----------------------------------------------------------------
  三、主要模块说明
----------------------------------------------------------------
1. bili_fetch.py
   - B 站 API 通用封装（headers、请求重试、wbi 签名机制）
   - 获取时空鉴权接口数据（mixin key、buv Cookie）
   - 定义 B 站 API 地址：video、user、stat、search、popular、rank
   - 封装 get_video、get_user、get_stat、search、popular、demo 等方法

2. deck_code.py
   - KARDS 卡组导入码解码器
   - normalize_deck_code：处理链接、URL 编码、游戏保存码（~ 扩展处理）
   - decode_deck_code：解码为 DecodedDeck，校验阵营、数量上限（40 卡不包括 HQ）
   - format_deck：中文卡组摘要输出
   - parse_and_format：解析 + 格式化一键调用

3. deck_image.py
   - 卡组解码后渲染图片：一张信息图 + 一张卡牌全图
   - render_deck_images(deck) -> (cards_path, info_path)
   - search_grid(items, name) -> 卡牌搜索网格图

4. dynamic_fetch.py
   - 动态客户端 DynamicClient
   - _fetch_page：拉取最新动态，防 B 站风控（412/352 HTTP）
   - _enrich：补全动态正文（提取转发原文、opus 详情）
   - fetch(limit=5) 拉取最新动态并缓存

5. dynamic_render.py
   - blank_image()：在插件数据目录生成纯白占位图
   - _pick_body / _pick_pics：提取动态的标题、正文、配图
   - split_paragraphs：按行切段，丢弃空行，保留顺序
   - group_segments：按段落+图片交错打包
   - build_segments / render_plain：组装分段结果

6. media_cache.py
   - ImageCache：动态配图本地缓存
   - _ensure_session、lookup：缓存命中时直接返回本地路径
   - download：下载单张图到 cache_root/dynamic_id/ 下
   - cache_item：缓存一条动态的全部配图（最多 9 张）
   - build_sheets：一张图片转为长图（宽度 720，高度上限 10000）
   - merge_pics：合并动态配图成少量长图

7. manual_deck.py
   - 手动卡组编辑：添加/移除/搜索卡牌、设置阵营、导入卡牌、别名管理
   - 数据来源：数据目录 deck_cards.json（运行时卡表）、card_aliases.json（别名库）
   - build_decoded：从本地卡组合成 DecodedDeck，供渲染使用
   - search_cards / find_cards：多条件搜索卡牌
   - set_permanent_id：为新导入卡牌生成 2 位临时 ID

8. main.py
   - BiliKards 主入口类
   - 初始化 DynamicClient 与 ImageCache
   - 处理所有聊天命令：kards deck / kards news / kards now / kards s
   - 私聊卡图识别流（`kards import <id>` 后送图即识别导入）

9. web_api.py
   - WebUI 页面桥接接口
   - recognize_card：接收卡图与 id，调用视觉模型识别后导入
   - 路由：catalog / aliases / alias/add / alias/remove / cards/import
       / cards/import-image / vision/providers / deck / add / remove / set / clear
       / render / thumb

----------------------------------------------------------------
  四、核心业务流程
----------------------------------------------------------------
一、卡组解析流程：
  用户输入解码器 → normalize_deck_code
            → strip 编码值、URL 参数 → strip extended（~扩展、补分号）
            → 以 %% 开头 → decode_deck_code
                 → 验证阵营编号（FACTION_CODE 映射 10 种）
                 → 按 "; " 拆分组，按 2 位短码拆解
                 → 计数 → 缺卡补空卡
                 → 按阵营/稀有度排序 → 校验：主卡组共 39 张（标准 40 含 HQ）
                 → 输出 DecodedDeck（含主/盟阵营、所有卡组条目、校验 warning）

二、卡组渲染流程：
  manual_deck.build_decoded(deck) → deck_image.render_deck_images(deck)
       → 渲染两张图（信息图卡组 + 卡牌全图）

三、动态查询流程：
  用户发“kards news <n>” 或“kards news list”
       → DynamicClient.fetch(limit) 拉取最新动态
       → _enrich 填充全文 + 配图
       → group_segments 拆段并搭配配图
       → 以“序号. 【标签】时间 标题”格式逐段链发

四、卡图识别流程：
  `kards import`（不带参数）→ 随机生成二位 base62 临时短码，当前会话 pending 有效期 1 分钟
       → 这 1 分钟内，同一发送者在该会话发送的所有图片都按该短码识别
       → 识别结果先存为草稿，不写入卡表；回复“同意”或 kards confirm 后才同步正式 ID
       → kards cancel / 回复“取消” 放弃草稿；kards setid <短码> <正式ID> 可在确认前改号
  `kards import <卡牌ID>` → 直接按指定 ID 识别并写入卡表
       → 未执行 import 命令时，仅当说明文字/文件名是卡表中已有的卡牌ID或导入ID才识别
       → 随机文件名、普通图片和机器人生成的图片不会误导入
       → 必须是完整卡图（含卡名/费用/攻防/描述文本框），只发插画、截图或动图会拒绝
       → card_crop 裁掉卡图外内容，多张卡拆成单张
       → web_api.recognize_card 每张卡分别调用视觉模型识别 JSON
       → 确认后 import_cards 合并进本地卡表
       → 显示逐张导入结果

   管理员权限与审核流程：
   - import / confirm / cancel / fix / setid 仅管理员可直接执行
   - 管理员判定：AstrBot event.is_admin() 或 data\cmd_config.json 的 admins_id
   - 其他用户执行上述命令不会改动卡表，而是生成 RV- 开头的审核编号
   - 管理员用 kards review 查看待审，kards approve <编号> 批准，kards reject <编号> 驳回
   - 附图导入在提交时已识别为草稿，批准后直接写入，无需重发图片
   - 待审队列保存在 data\plugin_data\bilikards\admin_reviews.json
   - kards fix <卡牌> 查看字段是只读操作，所有人可用

----------------------------------------------------------------
  五、命令速查
----------------------------------------------------------------
  kards deck 码组码      解析卡组码 + 卡图 + 信息图
  kards news <n>        看倒数第 n 条动态（1-20）
  kards news list       列出动态标题和序号
  kards now <关键词>     搜索 KARDS 相关视频
  kards s <关键词>      搜索本地卡表（含别名/描述/标签/属性）
                         超过 15 张自动分页，发 # 查看下一页
                         发 #第N个 单独看第 N 张卡的卡图+JSON
                         只命中 1 张时直接发单卡图+JSON
  kards alias 卡名 ～ 别名  给卡牌加别名
  kards alias list       查看别名库
  kards alias del 别名   删除别名
  kards import          生成二位临时短码，发卡图后出草稿（不立即写卡表）
  kards import <ID/JSON/文件名>  按指定 ID 导入，或发完整卡图自动识别
  kards confirm / 回复“同意”    把草稿同步到正式卡表
  kards cancel          放弃待确认草稿
  kards fix <字段> <新值>              修改刚导入卡牌的识别错误
  kards fix <卡牌> <字段> <新值>       修改指定卡牌字段
  kards setid 临时ID/卡名 永久ID       设置新卡永久 ID
  kards review           管理员查看待审核请求
  kards approve <编号>   管理员批准（驳回用 kards reject <编号>）
  kards add 卡名 [x2]   手动卡组加卡（衍生牌不可加入）
  kards del 卡名 [x2]   手动卡组删卡
  kards list / show     查看手动卡组文字 / 图片
  kards clear           清空手动卡组
  kards setmain 国家 / setally 国家  设置手动卡组主国 / 盟国
                          卡组按用户隔离（聊天按平台+发送者，网页按账号）
  kards 刷新动态         跳过缓存，重新拉取官方动态

----------------------------------------------------------------
  六、错误提示示例
----------------------------------------------------------------
  - 卡组码必须以 %% 开头，或形如 53|...（| 也可写 ～）
  - 卡组码缺少 | 分隔符（也可写 ～）
  - 普通 ID 须为 2 位字母或数字（卡组码兼容）
  - 找不到卡牌：未指定要设置永久 ID 的卡牌
  - 导入失败：不能在 deck_cards.json 缺失的牌短码处手动添加
  - 视觉模型调用失败：请在 AstrBot 中添加支持图片的模型，或填写 vision_provider_id

  所有 kards 子命令、watch 开关和 oc 指令也已注册为 LLM 工具
  （kards_* / watch_* / oc_*），开启工具调用的模型可直接调用。
